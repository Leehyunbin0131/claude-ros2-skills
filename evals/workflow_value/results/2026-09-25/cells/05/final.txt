`PowerReading` now carries `power_w` (watts) and `valid`. Both `normalize` helpers and both `monitor` nodes output the power in watts when `valid` is true and NaN when it is false. A clean build and `colcon test`, run the way CI runs them, pass, and both nodes gave the right values when I ran them.

## What I changed
- **`src/power_interfaces/msg/PowerReading.msg`**: replaced `float64 power_mw` with `float64 power_w` and added `bool valid`, each with a comment.
- **`src/power_interfaces/CHANGELOG.rst`**: added a "Forthcoming" entry at the top that notes this breaks existing consumers. I left the version numbers alone, as CONTRIBUTING asks.
- **`power_cpp_monitor`**:
  - `src/conversion.cpp`: `normalize()` returns `std::numeric_limits<double>::quiet_NaN()` when `!msg.valid`, otherwise `msg.power_w`.
  - `conversion.hpp`: doc comment updated.
- **`power_py_monitor`**:
  - `conversion.py`: `normalize()` returns `math.nan` when not `valid`, otherwise `msg.power_w`. I removed the `SCALE` constant because nothing uses it now.
- **Tests**: in both packages, the old milliwatt test is replaced by one valid case (12.5 W → 12.5) and one invalid case (→ NaN).
- **Nodes**: no code changes needed, since both already publish whatever `normalize()` returns. Function names, executables and topic names are the same as in the README.

## How I verified it
Your shell has this workspace's old `install/` sourced, which would test against the old message. So I copied the tracked sources into a temporary directory and ran everything in a fresh environment with only `/opt/ros/jazzy` sourced, as CI does:

1. **`colcon build`**: all 3 packages built. The only warning was the "Unknown distribution option: 'tests_require'" message, which comes from the existing `setup.py`.
2. **`colcon test --return-code-on-test-failure --python-testing pytest`**: exited 0. `colcon test-result` counted 5 results with 0 failures, and the result files confirm all four new tests ran and passed (two gtest cases, two pytest cases).
3. **Running the nodes**: I ran both `monitor` executables, published `{power_w: 12.5, valid: true/false}` on `/sensor/power`, and read the outputs:

| Topic | valid: true | valid: false |
|---|---|---|
| `/monitor/py_power_w` | 12.5 | .nan |
| `/monitor/cpp_power_w` | 12.5 | .nan |

I deleted the temporary directory afterwards.

## Things to know
- **Your `install/` is out of date.** I didn't touch `build/` or `install/`, so your terminal still has the old `power_mw` message. Run `colcon build` in the workspace and re-source `install/setup.bash` (or open a new terminal) before using the nodes.
- **Readings default to invalid.** A `bool` field defaults to `false`, so any publisher that doesn't set `valid` will now get NaN. Every sensor publisher and downstream tool must switch to `power_w` (watts, not milliwatts) and set `valid: true`.
