The message now carries `temperature_c` (degrees Celsius) and `valid`, and both `normalize` helpers and both `monitor` nodes output degrees Celsius for a valid reading and NaN for an invalid one. A clean build, the full test suite and a live run of both nodes all passed. Nothing is committed.

## What I changed (sources only)

- **Tests**: I replaced the old millidegree test in each package with two tests: a valid 21.5 °C reading must give 21.5, and an invalid reading must give NaN (checked with `isnan`).

## Things to know

- **This is a breaking interface change.** Anything else that publishes or subscribes to `/sensor/thermal` must be rebuilt against the new message and set `valid`. An old binary won't match the new type.
- **Two pre-existing issues I left alone:**
  - The build prints a warning about `tests_require` in `setup.py`. It's harmless because CONTRIBUTING's test command passes `--python-testing pytest`.
  - `thermal_cpp_monitor` installs the `conversion.hpp` header but not the `thermal_cpp_monitor_conversion` library, and doesn't export it. Outside C++ code can include the header but can't link `normalize`. That doesn't affect this change, but it conflicts with the README saying other tools call the helpers directly.
