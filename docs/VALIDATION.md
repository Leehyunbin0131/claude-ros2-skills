# Evidence Tool Operational Validation

The evidence tracking implementation (`evidence.py`) was validated against an independent suite of 39 contract tests (`tests/test_evidence.py`) covering snapshots, missing inputs, exclusions, symlink handling, and status transitions. A mutation control removing three fixes caused four relevant tests to fail (35 passing), confirming the test suite's sensitivity to regression bugs. In addition, colcon workflow tests (`tests/test_colcon_workflow.py`) include two unit test methods, with the new integration test evaluating both `passing_cpp` and `empty_cpp` CMake fixtures to verify empty-test rejection (rc 0 vs checker 2) and the detection of modified installation binaries under unchanged source trees (`changed: 1`). Package installation suites (`tests/test_install.py`) confirmed all 22 delivery and update checks across Claude Code and Codex, while acceptance oracles passed across both Seed 0 (3/3) and Seed 1 (3/3). Workflow value harness verification (`evals/workflow_value/test_runner.py` with `WV_ORACLE_CONTROLS=1`) passed all 14 tests in 487.5s, including a control method evaluating 12 matched cases, executed cleanly without code edits by pointing `WV_VENV_BIN` to the active colcon virtualenv.

Separately from the automated test suites, a single qualitative smoke observation (n=1) was conducted using DeepSeek (`deepseek/deepseek-flash`) on a synthetic ROS 2 workspace where the prompt specified no real robot was involved. A configuration parameter was modified from 0.5 to 1.5 while source files remained untouched. `evidence.py inspect` correctly reported `record_status: "changed"` (exit code 1) and isolated the modified configuration file. The agent then independently re-ran the declared Python check and observed the resulting assertion failure. In this observation, the agent also proposed additional colcon packaging steps—interpreted by reviewers as scope expansion beyond the narrow snapshot inspection—and noted unset ROS variables in the `parentenv` snapshot as a sign that the check ran outside ROS, overlooking that parent-shell records do not capture child-process sourcing. This qualitative session had no baseline comparison, licenses no inference regarding developer productivity gains, and no follow-up model comparison was conducted after amending the review instructions.
